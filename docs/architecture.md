# Architecture

## Boundaries

- `client/`: React UI, routing/navigation, reading presentation, safe text selection and form fallback, import feedback, review reveal/rating. Plain text rendering only; no HTML execution.
- `shared/types.ts`: API-facing Article → Segment → suggested Vocabulary, Article → Analysis, saved Vocabulary → LearningProgress types.
- `server/schema.ts`: strict Zod validation and actionable errors. Data is untrusted even when generated by ChatGPT.
- `server/store.ts`: domain operations and transactions. Only this layer creates cards or applies grades.
- `server/database.ts`: SQLite connection and ordered migrations via `PRAGMA user_version`.
- `server/app.ts`: JSON API, input validation, origin/host guards and security headers.
- `fixtures/`: original synthetic source material. No real a16z article content.
- `content/articles/`: version-controlled, reviewed portable knowledge JSON and derived Markdown.
- `scripts/`: validate, stage, import the archive, query, adapt observed upstream, and back up SQLite.

## Why these components

React and Vite keep the UI simple and inspectable. Express supplies a small same-origin API. Native Node SQLite avoids a separate service and native npm build prerequisites. The Git knowledge archive is the portable authority for accepted article content; SQLite is the running index and authority for private learning state, not browser-local storage. ts-fsrs 5.4.2 is reused directly for FSRS-6 scheduling, with fuzz disabled for reproducibility; no handwritten scheduling formula is substituted.

KISS Translator (GPL) and Folo (AGPL) informed requirements only. No code or assets were copied. Readability and Dexie are deferred because upstream already supplies structured bilingual content, and device-local caching is not yet needed. No scraping, model endpoint, translation cost, or credential setup is required.

## Relational ownership

`articles` stores validated source JSON with stable IDs, integer revisions, and a SHA-256 content hash. `article_state` stores separate personal read/favorite state. `saved_vocabulary` stores a source-context snapshot and its own user meaning/favorite. `learning_progress` stores the ts-fsrs card plus an optimistic revision. `review_events` stores idempotency key, request, resulting snapshot, scheduling log, and UTC timestamp.

Imported vocabulary is suggested source data. Saving creates a separate learner-owned record. New source revisions may change/remove paragraphs without destroying that saved record or old context. Different terms or different source paragraphs can have separate cards; a normalized identical term within the same article/paragraph is intentionally one card. Multiple senses inside one paragraph require future explicit sense IDs.

## Transactions and repeated operations

Import validates the entire batch before opening a transaction. A duplicate article ID in one batch is an error. A matching revision and content is idempotent; same revision with changed data and older revisions fail the batch. A higher revision replaces source data, not learning state. A conflict late in the batch rolls back earlier writes.

A review requires `event_id`, `rating`, and `expected_revision`. Inside `BEGIN IMMEDIATE`, exact request replays return the original result, changed reuses of the event ID fail, stale cards fail, and early reviews fail. The server owns review time and advances the card with ts-fsrs; the event and card update commit together. Cards are restored with Date instances before calling the scheduler.

## Deliberate limits

- Small personal library: article JSON is parsed for filtering; this is not a high-scale full-text search service.
- Single server/process ownership; no offline write merge or cross-device conflict reconciliation beyond optimistic review revisions.
- No user accounts. Loopback guards are a local boundary, not remote authentication.
- The observed simplified upstream 1.0 example has a dedicated rights-aware adapter. Full formal specification and representative daily-export compatibility remain unverified.
- User-entered rights claims cannot prove copyright authorization.
