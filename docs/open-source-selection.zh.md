# a16z 双语阅读器：开源选型建议

核查日期：2026-10-08。上游已经提供结构化双语 JSON，因此 MVP 应直接导入现有内容，围绕阅读、词汇收藏和复习完成闭环。建议复用 **ts-fsrs**，参考 Folo 与 KISS Translator 的交互；Readability 留作未来导入网页的可选能力，Dexie 仅作可选浏览器缓存。现阶段无需建设抓取器、在线翻译服务或自研 SRS 算法。

| 项目 | 已核实许可证 | 维护信号 | 对本项目的用途与结论 |

| [Folo](https://github.com/RSSNext/Folo) | AGPL-3.0-only，另有资产限制 | 默认分支提交 2026-10-07；桌面版 1.15.0 发布 10-02 | **参考**文章库、已读/收藏状态及双语展示。完整应用较重，不建议整体分叉 |
| [KISS Translator](https://github.com/fishjar/kiss-translator) | GPL-3.0 | 默认分支提交 2026-10-06；v2.1.0 发布 09-24 | **参考**段落对照、原译文切换及选词交互。MVP 已有译文，不接入其翻译运行时 |
| [Mozilla Readability](https://github.com/mozilla/readability) | Apache-2.0 | 默认分支提交 2026-07-09；包/更新日志为 0.6.0，日期 2025-03-03 | **后续可选**网页正文提取。当前 JSON 导入不需要；它也不是 HTML 安全净化器 |
| [Dexie](https://github.com/dexie/Dexie.js) | Apache-2.0 | 默认分支提交 2026-09-28；v4.4.6 发布 09-10 | **可选复用** IndexedDB 缓存与离线读取，不承担多设备唯一数据源 |

五个仓库均未归档。维护信号不等于安全审计。MIT、Apache 组件应保留许可证和适用声明；GPL/AGPL 代码复制或改编可能带来相应开源义务，所以建议仅参考行为、独立实现界面。尤其 [Folo 的许可证](https://github.com/RSSNext/Folo/blob/dev/LICENSE)明确限制 `icons/mgc` 资产再分发，不能照搬其图标。软件许可也不自动覆盖文章内容或品牌资产。

## 存储选择

长期使用的建议是：**SQLite 保存权威数据，JSON 负责导入导出，Markdown 负责可读归档**。

- Markdown 适合文章与笔记，便于人工阅读；不适合维护复习队列、关联约束及原子更新。
- JSON 与现有上游格式最贴合，适合交换、备份和测试样本；文件本身没有事务、索引或多端冲突处理。
- SQLite 适合保存文章、词汇及复习记录，可将一次评分和卡片新状态一起提交。多设备通过同一小型服务访问数据库，而非同时修改网盘中的数据库文件。
- IndexedDB/Dexie 按浏览器和站点保存数据。换手机、浏览器或站点地址不会自动带走数据；清理浏览器也可能删除记录。因此缓存不能称为云备份。

SQLite 的多端方案仍需持久磁盘、访问控制及可恢复备份；临时运行环境里的数据库文件不够。先采用在线写入可减少同步复杂度；离线复习若进入范围，再设计事件去重、确认和冲突处理。[SQLite 官方说明](https://www.sqlite.org/whentouse.html)支持通过应用服务提供访问，并提醒避免多台电脑直接并发访问同一网络文件。

## 模块边界与下一步

建议链路为：**双语 JSON 导入与校验 → 文章/段落数据层 → 双语阅读界面 → 词汇及原文语境 → ts-fsrs 复习 → 持久化与导出**。缓存位于数据层外侧，之后可以增减，不改变业务数据契约。

导入时保留上游原文、译文及关联关系；展示时按已有段落对应关系成对渲染，不把两篇独立文本靠滚动位置“对齐”。收藏词汇与复习评分分开处理，保存单词不应自动算一次成功复习。每次真实评分保留复习事件，再更新卡片状态，便于恢复和升级。

**目前唯一缺少的数据兼容性材料是现有 `schema1.0`。** 拿到定义和代表性样本后，核对段落标识、原译文关系、词汇关联及版本规则，再确定适配与迁移；现在不另造一套替代 schema。当前交付为选型研究，尚未实现或部署。

详细维护证据、源码边界和许可证链接见英文研究附录；其中抓取和翻译扩展讨论仅供未来参考，不属于本次 MVP 前置条件。
